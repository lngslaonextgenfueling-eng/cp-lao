# PC SHOP — Marketplace Platform (ຫຼາຍຮ້ານຄ້າ)

ແພລດຟອມຂາຍຄອມພິວເຕີ & ອຸປະກອນໄອທີ: ຜູ້ຂາຍສະໝັກເປີດຮ້ານເອງ, Admin ອະນຸມັດ ແລະ ເກັບຄ່າທຳນຽມ, ລູກຄ້າຊື້ຈາກຫຼາຍຮ້ານໃນກະຕ່າດຽວ.

Tech stack: **Next.js 14 (React) + Tailwind CSS** · **Express + TypeScript** · **PostgreSQL + Prisma**

```
pc-shop/
├── docker-compose.yml     # PostgreSQL
├── backend/               # REST API (port 4000)
└── frontend/              # Next.js (port 3000)
```

## ກົດການເຮັດວຽກຂອງ Marketplace

- ຮ້ານໃໝ່ມີສະຖານະ **ລໍຖ້າອະນຸມັດ** — ສິນຄ້າຍັງບໍ່ປາກົດຈົນກວ່າ Admin ອະນຸມັດ. ຮ້ານທີ່ຖືກ **ລະງັບ** ຈະຊ່ອນສິນຄ້າທັນທີ.
- ກະຕ່າດຽວທີ່ມີສິນຄ້າຫຼາຍຮ້ານ → ລະບົບ **ແຍກເປັນອໍເດີຕໍ່ຮ້ານ** (ໃຊ້ `groupId` ດຽວກັນ). ຄ່າຈັດສົ່ງຄິດຕໍ່ຮ້ານ.
- ຄູປອງເປັນຂອງແພລດຟອມ: ຫັກ % ຈາກຍອດຂອງແຕ່ລະຮ້ານ.
- **ຄ່າທຳນຽມ** = `(ຍອດສິນຄ້າ − ສ່ວນຫຼຸດ) × commission%` ຂອງຮ້ານນັ້ນ (ຄ່າເລີ່ມຕົ້ນ 5%) ບັນທຶກໃນ `Order.platformFee` ຕອນສັ່ງຊື້.
- ເງິນຈາກລູກຄ້າໂອນເຂົ້າ **ບັນຊີຂອງແຕ່ລະຮ້ານໂດຍກົງ**; ຮ້ານເປັນຜູ້ກົດຢືນຢັນ “ຊຳລະແລ້ວ”. ຄ່າທຳນຽມທີ່ແພລດຟອມຕ້ອງເກັບຈາກຮ້ານ ຕ້ອງຈັດການນອກລະບົບ (ຕົວຢ່າງ: ເກັບລາຍເດືອນຕາມຍອດ `platformFee` ໃນໜ້າ Admin).
- **ຂັ້ນຕອນສະຖານະອໍເດີ**: ລໍຖ້າຊຳລະ → ຊຳລະແລ້ວ → ກຳລັງຈັດສົ່ງ → ສຳເລັດ (COD ສົ່ງກ່ອນຊຳລະໄດ້). ຍົກເລີກໄດ້ກ່ອນ “ສຳເລັດ” ເທົ່ານັ້ນ. “ສຳເລັດ” ແລະ “ຍົກເລີກ” ແມ່ນສະຖານະສຸດທ້າຍສຳລັບຮ້ານ; Admin ຖອຍຫຼັງໄດ້ 1 ຂັ້ນເພື່ອແກ້ໄຂຄວາມຜິດພາດ.
- ຍົກເລີກອໍເດີ → ຄືນສະຕັອກອັດຕະໂນມັດ **ຄັ້ງດຽວເທົ່ານັ້ນ** ເຖິງວ່າຮ້ານ ແລະ Admin ກົດພ້ອມກັນ. ຜູ້ຂາຍສັ່ງຊື້ສິນຄ້າຂອງຮ້ານຕົນເອງບໍ່ໄດ້.
- ສິນຄ້າທີ່ມີໃນອໍເດີແລ້ວ ຈະ **ຖືກຊ່ອນ** ແທນການລົບ ເພື່ອຮັກສາປະຫວັດອໍເດີ.

## ເລີ່ມໃຊ້ງານ

### ເປີດໃຊ້ງານຈິງ (server + ໂດເມນ + HTTPS)

ເບິ່ງ **[DEPLOY.md](DEPLOY.md)**: ຄູ່ມືທຸກຂັ້ນຕອນ ຕັ້ງແຕ່ຊື້ໂດເມນ, ເຊົ່າ VPS ຈົນເຖິງ `sudo ./install.sh`.

### ພັດທະນາໃນເຄື່ອງ

```bash
# 1) Database
docker compose -f docker-compose.dev.yml up -d

# 2) Backend
cd backend
cp .env.example .env
npm install
npx prisma db push            # ສ້າງຕາຕະລາງ
npm run db:seed               # ຂໍ້ມູນຕົວຢ່າງ: 2 ຮ້ານ + ສິນຄ້າ + ຄູປອງ + admin
npm run dev                   # http://localhost:4000

# 3) Frontend (terminal ໃໝ່)
cd frontend
cp .env.example .env.local
npm install
npm run dev                   # http://localhost:3000
```

### ຖ້າເຄີຍຣັນເວີຊັນເກົ່າ (ຮ້ານດຽວ) ມາກ່ອນ

ໂຄງສ້າງຖານຂໍ້ມູນປ່ຽນ (ສິນຄ້າ/ອໍເດີຕ້ອງມີ `shopId`) — ໃຫ້ລ້າງຖານຂໍ້ມູນຕົວຢ່າງ ແລ້ວສ້າງໃໝ່:

```bash
cd backend
npx prisma db push --force-reset   # ⚠️ ລຶບຂໍ້ມູນທັງໝົດ
npm run db:seed
```

### ທົດສອບ flow ເຕັມ

1. ສະໝັກສະມາຊິກໃໝ່ → ເມນູ “ເປີດຮ້ານຂາຍ” → ສົ່ງຄຳຂໍ (ສະຖານະ ລໍຖ້າອະນຸມັດ).
2. ເຂົ້າ `/admin` ດ້ວຍ Admin → ແຖບ “ຮ້ານຄ້າ” → ອະນຸມັດ.
3. ກັບໄປ `/seller` ດ້ວຍບັນຊີຜູ້ຂາຍ → ກົດ “ກວດສອບສະຖານະ” → ເພີ່ມສິນຄ້າ.
4. ຊື້ສິນຄ້າຈາກ 2 ຮ້ານໃນກະຕ່າດຽວດ້ວຍບັນຊີລູກຄ້າ → ກວດວ່າແຍກເປັນ 2 ອໍເດີ.
5. ເຂົ້າ `/seller` ຂອງແຕ່ລະຮ້ານ → ປ່ຽນສະຖານະອໍເດີ; ເບິ່ງຄ່າທຳນຽມໃນ `/admin`.

## ໝາຍເຫດ

- **ຄວາມປອດໄພ**: ໃນ production (`NODE_ENV=production`) API ຈະ**ບໍ່ຍອມເປີດ** ຖ້າ `JWT_SECRET` ຫວ່າງ, ເປັນຄ່າຕົວຢ່າງ ຫຼື ສັ້ນກວ່າ 32 ຕົວ. Login/ສະໝັກ/Google ຈຳກັດ 10 ຄັ້ງ / 15 ນາທີ / IP. Google Login ຮັບສະເພາະອີເມວທີ່ Google ຢືນຢັນແລ້ວ. ກ່ອນເປີດໃຊ້ຈິງ ໃຫ້ປ່ຽນລະຫັດບັນຊີຕົວຢ່າງ ແລະ ໃຊ້ HTTPS (ຕົວຢ່າງ nginx/Caddy ຢູ່ໜ້າ).

- **QR Code / Payment Gateway**: ຕອນນີ້ສະແດງເລກບັນຊີຂອງຮ້ານ + ບ່ອນວາງ QR; ຮ້ານຢືນຢັນຊຳລະດ້ວຍມື. ການເຊື່ອມ BCEL OnePay ອັດຕະໂນມັດ (ແລະ ການແບ່ງເງິນໃຫ້ຮ້ານ/ແພລດຟອມ) ຕ້ອງສະໝັກ merchant ກັບທະນາຄານ.
- **Google Login**: ໃສ່ `GOOGLE_CLIENT_ID` (backend) ແລະ `NEXT_PUBLIC_GOOGLE_CLIENT_ID` (frontend); ຖ້າບໍ່ໃສ່ ປຸ່ມຈະບໍ່ສະແດງ.
- **ຮູບສິນຄ້າ**: ໃສ່ URL ຮູບ; ຖ້າຫວ່າງຈະສະແດງໄອຄອນ.
- ລາຄາເກັບເປັນຈຳນວນເຕັມ ສະກຸນເງິນກີບ (₭).
